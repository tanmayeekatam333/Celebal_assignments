# E-Commerce Order Analytics System

An end-to-end data analytics pipeline: synthetic data generation with
intentional data-quality issues, Pandas-based cleaning/validation, a SQLite
warehouse, 16 SQL analysis queries (joins, window functions, CTEs, cohort
analysis), a CLI reporting tool, and an edge-case test suite.

## Setup
```bash
pip install -r requirements.txt
```

## Run order
All commands assume you're in the repo root.

```bash
python3 src/generate_data.py                # -> data/raw/*.csv
python3 src/clean_data.py                   # -> data/processed/*_cleaned.csv + data_quality_report.txt
python3 src/load_db.py                      # -> data/ecommerce.db (SQLite)
python3 src/report_cli.py --type monthly --start 2026-06-01 --end 2026-06-30
python3 tests/test_edge_cases.py
```

`report_cli.py` also runs fully interactively with no flags (prompts for
type/start/end), and accepts `--db <path>` to point at a different database.

To inspect or re-run the 16 SQL queries directly:
```bash
sqlite3 data/ecommerce.db < sql/analysis.sql
```

## Data issue rates (as generated)
- 5% orders: NULL `customer_id`
- 3% order_items: negative quantity (returns)
- ~4% orders: `DD-MM-YYYY` date format
- ~15% products: extra spaces / mixed case in name
- 2% customers: invalid email
- 6 order_items: reference non-existent `order_id`
- 5 orders: future-dated

## Notes on reproducibility
`generate_data.py` seeds Python's `random` module (`seed(42)`), so re-running
it produces the same dataset. If you regenerate, re-run `clean_data.py` and
`load_db.py` afterward so `data/processed/` and `data/ecommerce.db` stay in
sync with the new raw data.
